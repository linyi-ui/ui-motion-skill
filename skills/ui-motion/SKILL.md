# UI/UX动效交互

你的目标：做出的交互要有细节、有手感、经得起慢放，不是"点一下就硬切"。

## 工作方式
1. 先读需求，用一句大白话告诉用户你打算加哪几个动效、为什么。用户确认后再写代码。
2. 从 `references/motions.md` 动效库里挑最合适的写法，严格按里面的参数实现（时长、曲线、间隔）。库里没有的，按 `references/foundations.md` 的底线规则自己设计。
3. 交付前按 `references/anti-cheap.md` 逐条自检，不合格就改。

## 场景判断（怎么选动效）

用户说要做某个功能时，按下面的对照表快速判断该用哪个动效：

| 用户需求 | 推荐动效 | 不用的情况 |
|---|---|---|
| 悬浮按钮展开菜单 | 变形菜单 Morph Menu | 菜单项超过 6 个 / 需要二级菜单 |
| 列表卡片点开详情 | 卡片展开 Expand Card | 表格行 / 详情页和列表差别太大 |
| 点赞、收藏、关注 | 点赞爆粒子 Like Burst | 严肃场合 / 按钮很小 |
| 提交表单、支付、保存 | 提交按钮三连变 Submit Morph | 即时操作 / 不需要反馈 |
| 设置开关、深色模式 | 果冻开关 Jelly Toggle | 三态/多选 / 需要立即显示结果 |
| 删除、注销、清空 | 长按确认 Hold to Confirm | 非危险操作 / 需要二次确认 / 批量操作 |
| 列表下拉获取新内容 | 下拉刷新 Pull to Refresh | 内容很少变化 / 实时推送 / 电脑网页为主 |
| 列表单行快捷删除、归档 | 左滑删除 Swipe to Delete | 重要数据不可恢复 / 电脑网页为主 / 行本身能横滑 |
| 一张张二选一（喜欢/跳过） | 卡片左右滑 Swipe Cards | 需要对比多个选项 / 超过两种结果 |
| 用户自己调整列表顺序 | 拖拽排序 Drag to Reorder | 列表有固定排序 / 条目上百条 |
| App / 小程序底部主导航 | 水滴导航 Liquid Tab Bar | Tab 超过 5 个 / 电脑网页顶部导航 |
| 选规格、选日期、分享、筛选面板 | 底部弹窗 Bottom Sheet | 内容像独立页面一样长 / 电脑大屏 / 只是一句提示 |
| 头图 + 大标题的详情页 | 吸顶大标题 Collapsing Header | 没有头图 / 表格表单类页面 |
| 顶部分段标签 + 左右滑内容页 | 毛毛虫标签 Segmented Tabs | 标签超过 5 个 / 每页内容本身要横滑 |
| 信息流、列表、详情页首次加载 | 骨架屏扫光 Skeleton Shimmer | 加载 <300ms / 版面结构不固定 |
| 照片墙、商品图、头图等网络图片 | 模糊到清晰 Blur-up Image | 图标、Logo / 已缓存的图 |
| 分页的长列表滑到底 | 加载更多 Infinite Scroll | 需要跳页或看总数 / 底部有重要内容 |
| AI 对话、边生成边显示的回复 | AI 流式回复 Streaming Reply | 回复很短 / 代码块、表格 |
| 外卖、商品、服务评价打分 | 星级评分 Star Rating | 1–10 分精确打分 / 只有好坏两种 / 只读展示 |
| 注册、设置或修改密码 | 密码强度条 Strength Meter | 登录页密码框 / 数字支付密码 |
| 邮箱、用户名、手机号等格式校验或查重 | 实时打勾 Inline Validation | 密码框 / 没有对错的自由文本 |
| 登录、注册、资料等文本输入框 | 浮动标签 Floating Label | 搜索框 / 很矮的行内编辑框 |
| 密码错误、验证码错误等提交后报错 | 输错摇头 Shake on Error | 还在输入时的格式问题 / 网络或服务器错误 |
| 短信、邮箱验证码，两步验证 | 验证码格子 OTP Input | 长度不固定或含字母的长码 |
| 打卡、支付、完成任务、升级等庆祝时刻 | 撒花庆祝 Confetti | 普通保存提交 / 负面结果 / 高频操作 |
| 删除消息、撤回、清除卡片想要仪式感 | 碎沙删除 Disintegrate | 批量删除 / 元素很大、低端设备 |
| 官网首页、发布页、启动页的品牌 Logo | 粒子 Logo Particle Logo | 后台和表单页 / Logo 很小 / 首屏要立刻看清 |
| 记账、运动、销售等柱状图第一次出现 | 柱子长出来 Bar Grow | 柱子超过 20 根 / 实时刷新的监控图 |
| 收益、体重、股价等走势折线图，拖动看数 | 折线画出来 Line Draw + Scrub | 列表里的迷你走势线 / 数据点少于 5 个 |
| 支出分类、流量来源等占比环形图 | 圆环转出来 Donut | 分类超过 7 个 / 需要精确比较大小 |
| 看板切换周/月/年、切换指标、筛选后刷新 | 切换变形 Data Morph | 前后数据完全不相关 / 上百根柱子 |
| 首页、列表、落地页往下滑时内容出现 | 依次浮现 Scroll Reveal | 首屏内容 / 聊天、表格等要立刻看清的内容 |
| 官网首屏、活动页想要立体纵深感 | 视差纵深 Parallax | 后台、表单页 / 低端手机为主的长列表 |
| 品牌故事、产品理念的一大段核心文案 | 逐字点亮 Scroll Text Reveal | 正文、说明文档 / 超过 3 行的普通段落 |
| 产品发布页、功能介绍分几段讲卖点 | 钉住换图 Sticky Scroll | 手机窄屏没有左右空间 / 卖点少于 3 个 |
| 官网首屏、落地页的主按钮（电脑端悬停） | 磁吸按钮 Magnetic Button | 手机和小程序 / 一排很多按钮挨在一起 |
| 电商加入购物车 | 加购飞入 Add to Cart Fly | 批量加购 / 屏幕上看不到购物车图标 |
| 音乐、播客、视频的播放暂停 | 播放暂停变形 Play ⇄ Pause Morph | 16px 以下小图标 / 列表里非当前播放的歌 |
| App 右下角加号展开几个快捷操作 | 悬浮按钮展开 FAB Fan Menu（想要按钮变成面板就用变形菜单） | 选项超过 5 个 / 有二级菜单 |
| 代码、邀请码、链接、优惠码的复制按钮 | 复制变勾 Copy → Copied | 按钮在菜单里一点就关 |
| App、小程序打开时的启动页 | 启动页进首页 Splash → Home | 热启动 / 首页数据要等很久 |
| 点开详情、切换页面时的等待 | 顶部进度条 Top Progress Bar | 加载 <300ms / 首次加载能用骨架屏 |
| 发帖、发朋友圈的多张图片上传 | 照片上传进度 Upload Progress | 几分钟的大视频上传 |
| 聊天发消息、评论、点赞等大概率成功的操作 | 消息秒发 Optimistic Send | 支付、下单等必须等结果的操作 |
| 打车、派单、配对等等待对方响应 | 叫车等待 Ride Matching | 等待 <1 秒 / 没有地图或空间关系 |
| 评论、动态、群聊里输入 @ 提及好友 | @好友联想 Mention Picker | 只能 @ 固定几个人 / 不能插入富文本 |
| 评论下的二级回复、线程回复展开收起 | 展开楼中楼 Thread Expand | 一次展开超过 20 条 / 回复要跳新页面看 |
| 评论、消息的表情回应 | 长按表情回应 Reaction Picker（只有点赞就用点赞爆粒子） | 只有一种回应 / 长按已被占用 |

**如果库里没有对应的动效**，按 `references/foundations.md` 的通用规则设计：
- 小元素 150–250ms，面板 300–450ms，转场 450–600ms。
- 进场 ease-out，退场 ease-in，弹性用轻微回弹（超调不超过 8%）。
- 只动 transform 和 opacity，避免改 width、height。
- 一组元素依次出现，间隔 30–60ms。

## 动效底线（所有动效都要满足）
- 有来源：元素从哪里来、回哪里去要讲得通。按钮变成菜单，就是按钮本身在变形，不是凭空弹出新的一层。
- 有层次：一组元素依次出现，间隔 30–60ms，不要一起蹦出来。
- 有曲线：禁止 linear。进场用 ease-out，退场用 ease-in，需要弹性用轻微回弹（超调不超过 8%）。
- 有分寸：小元素 150–250ms，面板和卡片 300–450ms，整页转场 450–600ms，任何动效都不超过 700ms。
- 可逆：打开怎么来，关闭就怎么回去，路径一致。
- 只动 transform 和 opacity，避免改 width、height、top 这类属性导致卡顿。确实需要改尺寸时用 FLIP 技巧。
- 尊重系统设置：`prefers-reduced-motion: reduce` 时，动画改成 150ms 以内的淡入淡出。
- 有反馈：可点击的元素要有按下态（缩放到 0.96–0.98）和 hover 态，触屏上有点击反馈。
- 手势要跟手：拖动时元素 1:1 跟着手指（需要阻力时加阻尼），松手后按"距离阈值 + 滑动速度"判断是回弹、吸附还是甩出，绝不直接跳位。周围元素要实时让位或补位。用 Pointer Events 实现，鼠标和触屏都能用。
- 等待要有内容：结构已知时用骨架屏而不是白屏转圈，图片框提前占位，内容到了分块错开出场，加载前后布局不跳；操作后 100ms 内必须有可见反馈。
- 页面切换要有空间关系：新内容从哪个方向来、旧内容往哪退要和操作方向一致；弹出层出现时背后页面要跟着退后（缩小、压暗），不能一动不动。指示器（胶囊、下划线）要"流"过去，不要瞬移。
- 粒子要有来源和退场：粒子从触发它的元素里来（按钮、被删的消息、Logo 本身），有重力或阻力（先快后慢），每粒各自淡出，不整批消失；一个页面最多一处，全部画在一个 canvas 上，减少动效时不放。
- 图表要"长出来、变过去"：先出坐标再出数据，数据按阅读顺序依次出现（柱子从左到右、折线一笔画出、圆环顺时针），数字跟着图形一起滚动；数据切换时从旧形状变到新形状，不清空重画；能点的图表点了要有"被选中"的形变（弹出、加粗），不只变颜色；同一份数据只在第一次进入时播放。
- 滚动动效要跟手、只播一次：进场类（浮现）在元素真正露出一点时才触发，同组依次出发，播过不重播；进度类（视差、逐字点亮、钉住换图）进度完全由滚动位置决定，手停画面就停、往回滑就倒回去，不要自己按时间播放；用 IntersectionObserver 和 transform，不在 scroll 事件里改布局；减少动效时直接显示最终状态。
- 按钮要回应你：点下去不只是变个色或另外弹个提示框。反馈出现在按钮本身（变形、变勾、文字滚动换掉），或者有一个看得见的结果去向（东西飞进购物车、选项从按钮里依次弹出）；按钮尺寸变化要平滑，不一下跳；鼠标悬停类效果只给电脑端，触屏只保留按下态。
- 等待要让人觉得快：先把能给的结果立刻给出来（缩略图、发出去的消息、首页框架），原页面不要被白屏或遮罩盖掉；进度要看得见、会变化（细进度条先快后慢、照片一点点刷亮、波纹和小车在动），不要只有一个转圈加一句文字；结束时有衔接（冲线、对勾、收回、开过来），不要内容一下子硬换掉。
- 评论区要有来龙去脉：@ 名单从光标里弹出，选中的人变成一个整体（胶囊，一次删掉）；回复一条接一条垂下来，用竖线串起来，下面的内容平滑让位；表情回应能按住滑动选，选中的表情飞到它该去的地方，计数跳一下。不要整块蹦出来，也不要让人松手再点一次。
- 表单要等人说完：用户还没输完不报错（停止输入约 400ms 或离开输入框再校验），改对了立刻变绿；反馈就近出现在输入框旁边；错误用"动作 + 颜色 + 文字"三重提示，不只靠变红，不用 alert；标签用真正的 label 不用 placeholder；状态切换时输入框不改变布局高度。

## 输出要求
- 默认交付一个可以直接打开运行的单文件 HTML（CSS 和 JS 都写在里面），不依赖外部库；用户指定框架时按框架写。
- 动效参数集中写成 CSS 变量或常量（如 `--dur-panel: 400ms`），方便用户微调。
- 代码里给关键动效加一行中文注释，说明它模仿的是哪种交互。
- 代码要完整可运行，不用省略号跳过；关键逻辑加中文注释。
